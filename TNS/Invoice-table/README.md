# TNS — Анализ и нормализация данных накладных

Папка содержит артефакты кейса **«Анализ и нормализация данных накладных»**, подготовленного в рамках подготовки к позиции Ведущего системного аналитика.

## Назначение

Артефакты демонстрируют последовательность работы от **бизнес-анализа исходных данных и выявления бизнес-правил** до **системного анализа и проектирования структуры данных**.

Основной принцип: целевая модель данных формируется после фиксации и уточнения бизнес-правил, а не исходя только из структуры исходной таблицы.

## Состав артефактов

| Файл                                              | Назначение                                                                                      |
| :------------------------------------------------ | :---------------------------------------------------------------------------------------------- |
| `draft-brd-analiz-biznes-trebovanij-nakladnye.md` | BRD: бизнес-требования, бизнес-правила, выявленные вопросы и неопределённости                   |
| `draft-sa-sistemnyj-analiz-i-proektirovanie.md`   | SA: анализ исходных данных, зависимости, гипотезы нормализации и предварительное проектирование |
| `minimalnaya-testovaya-model-bd.md`               | Минимальная тестовая модель БД для проверки гипотез и зависимостей                              |
| `shop_db - shop_db - public.png`                  | Визуализация структуры тестовой БД                                                              |

## Последовательность работы

```text
Исходные данные
      ↓
Бизнес-анализ
      ↓
BRD + вопросы к заказчику
      ↓
Системный анализ
      ↓
Гипотезы структуры и зависимостей
      ↓
Тестовая модель БД
      ↓
Проверка гипотез
```

## Статус

Артефакты находятся в рабочем состоянии **draft** и предполагают дальнейшее уточнение после получения ответов на бизнес-вопросы.

Тестовая модель БД используется для проверки технических гипотез и не является утверждённой промышленной моделью данных.

## Примечание

Кейс намеренно разделяет **BA-часть** и **SA-часть**:

* BA — определение бизнес-смысла данных, правил, ограничений и открытых вопросов;
* SA — анализ зависимостей, формализация требований и проектирование технического решения.
