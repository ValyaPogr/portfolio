# Анализ расхождения данных при маршрутизации B2B-запросов

**Тип:** реальный рабочий кейс  
**Роль:** System Analyst  
**Контекст:** B2B API / интеграция / тестирование

## Ситуация

При тестировании новой логики группировки ответов B2B API
по макрорегионам необходимо было проверить сценарии,
в которых запросы обрабатываются разными экземплярами
backend-системы.

Тестовый стенд не позволял полностью воспроизвести
необходимую конфигурацию, поэтому часть сценария
проверялась на канареечном окружении.

## Задача

Проверить корректность маршрутизации запросов и последующей
группировки полученных ответов по макрорегионам.

## Действия

1. Проанализировала результаты тестирования и логи.
2. Сопоставила данные маршрутизации с данными БД.
3. Обнаружила расхождение в определении макрорегиона.
4. Исследовала закономерность возникновения ошибки.
5. Подключила коллег, отвечающих за соответствующие данные
   и компонент маршрутизации.
6. Определила необходимое изменение логики.
7. Дополнительно исследовала возможности настройки тестового
   стенда для воспроизведения сценариев по всем макрорегионам.
8. Подготовила инструкцию по настройке и передала её разработчикам
   и DevOps.

## Результат

- Ошибка обнаружена на этапе канареечного тестирования,
  до реализации решения на production для B2B-клиентов.
- Причина расхождения данных была локализована.
- Определена корректировка логики обработки данных.
- Создан способ воспроизводить необходимые сценарии
  на тестовом стенде.
