# Анализ расхождения данных при маршрутизации B2B-запросов

**Тип кейса:** System Analysis / Integration / API / Testing

## Контекст

В рамках разработки и тестирования B2B API необходимо было проверить корректность маршрутизации запросов и последующей группировки ответов по макрорегионам.

Запрос проходил через несколько интеграционных компонентов: система-инициатор → компонент маршрутизации → один из backend-экземпляров, соответствующий макрорегиону.

На тестовом стенде не удавалось полностью воспроизвести конфигурацию всех макрорегионов, поэтому часть сценариев дополнительно проверялась в безопасной канареечной среде.

## Проблема

При тестировании были обнаружены ошибки по отдельным регионам.

Анализ показал расхождение данных:

* компонент маршрутизации определял один макрорегион;
* в базе данных системы-инициатора был указан другой макрорегион.

Из-за этого система некорректно обрабатывала полученный ответ при группировке данных.

## Анализ

Для поиска причины были:

1. проанализированы результаты запросов и логи интеграционного взаимодействия;
2. сопоставлены данные маршрутизации и данные в базе системы-инициатора;
3. выявлена закономерность возникновения ошибки;
4. привлечены специалисты, отвечающие за базу данных и компонент маршрутизации;
5. подтверждено расхождение справочных данных;
6. дополнительно исследованы технические возможности настройки тестового стенда для воспроизведения сценариев по всем макрорегионам.

## Решение

На основании проведённого анализа была скорректирована логика обработки данных в системе-инициаторе.

Дополнительно была подготовлена инструкция по настройке и проведению тестирования сценариев для различных макрорегионов. Инструкция была передана разработчикам и DevOps для дальнейшего использования.

## Результат

* Ошибка обнаружена **до выхода решения в production для B2B-клиентов**.
* Причина проблемы локализована на уровне взаимодействия и согласованности данных между системами.
* Скорректирована логика обработки ответа.
* Создан воспроизводимый подход к тестированию сценариев с различными макрорегионами.
* Снижена вероятность повторного возникновения аналогичной проблемы при последующем тестировании.
